# 外部文档导入

知识库「导入文档」将文件转换为 Markdown 文章，并在 `/dashboard/imports` 保留逐文件任务。
**浏览器只上传原文件、选择图片策略和多模态模型和提交任务；解析、PDF 拆页/渲染、OCR、成文全部由服务端 Asynq Worker 执行。**
上传并成功提交任务后即可关闭页面，不依赖浏览器 Web Worker、WASM 或前端补图。
它与文档库上传、文章编辑器的覆盖导入是不同功能。

## 支持格式

支持范围对齐 [anydoc](https://github.com/firecrawl/anydoc)，另支持 Markdown：

| 格式 | 扩展名 |
| --- | --- |
| Markdown（不转换） | `.md`、`.markdown` |
| PDF | `.pdf` |
| Word | `.doc`、`.docx`、`.docm` |
| PowerPoint | `.ppt`、`.pps`、`.pot`、`.pptx`、`.pptm`、`.ppsx`、`.ppsm` |
| Excel | `.xls`、`.xlsx`、`.xlsm`、`.xlsb` |
| OpenDocument | `.odt`、`.ods`、`.odp` |
| RTF / EPUB / CSV | `.rtf`、`.epub`、`.csv` |

- Markdown 在服务器按 UTF-8 原样读取；非 Markdown 文件先直接转换，不先调用 OCR。
- Go 调用仓库内薄 Rust 程序 `petrichor-doc-convert`，使用固定版本 `anydoc = 0.2.4`。
  anydoc 的 Rust 核心不会调用 hosted OCR；不需要 Go SDK、Node、Python 或浏览器运行时。
- XLS/XLSB 使用 `Calamine = 0.36.1` 加服务器内兼容层：XLS 仅修正物理扇区范围外的旧式 FAT 填充，
  不更改实际数据链；XLSB 将短单元格记录补齐为显式列记录，避免 Calamine 跳过短记录造成漏列。
  保留工作表（含隐藏表）、单元格值与空列；后续仍校验数据链、加密和资源限额。
  公式仅读取缓存值，不执行宏、不重新计算公式。
- 已知内容限制采用明确失败而非部分成功：XLSX/XLSM 的隐藏工作表、隐藏行/列暂不支持；
  缺少必需部件或公式缓存的文件会失败；XLSB 的错误公式缓存记录（`BrtFmlaError`）暂不支持。
  这些预检针对已确认的上游漏读情况，不代表任意 Office 特性均可无损转换。
- PDF 使用 Poppler 按物理页拆分，逐页直接解析；图片检测独立于文字提取，文字解析成功也会保留图片。
  结构确定为空白的页直接保留空 Markdown，不消耗 OCR。
- Office、表格、EPUB 等没有稳定物理页码的格式按一个「文档单元」统计，不估算或虚构页数。
- 这是内容转换而非 Office 原版式复刻；嵌入图片遵循 anydoc 的 Markdown 序列化规则。

## 异步生命周期

1. 浏览器通过同源接口将原文件交给 Go，Go 有界接收到临时磁盘并保存至配置的对象存储；确认成功后，浏览器提交原件键、目标目录、图片策略、多模态模型和幂等键。
2. API 校验归属与参数，持久化零页任务及可运行状态，提交到现有 Asynq 文档导入队列。
3. Worker 下载原件、直接解析、拆分 PDF，并保存正文视觉区域及原页预览。
4. 完整准备成功后，原子发布页计划和总页数；文字与图片可同时存在，纯文字页立即完成。
5. 按任务的图片策略决定是否识别、保图；默认扫描页由多模态模型 OCR，正文图片由多模态分类，截图/扫描文字继续 OCR，照片/图表补描述。
6. 全部页成功后合并 Markdown，通过数据库事务创建文章；**文章落库成功才是 `completed`**。

阶段包括 `preparing`、`parsing`、`rendering`、`ocr`、`finalizing`、`completed`。
准备阶段总页数尚未确定时显示未知总量，不显示伪造百分比，也不把零页任务误判为已完成。
列表、详情和上传弹窗使用 Ruixen 的受控进度组件，服务端进度通过任务接口轮询。

### PDF 图片策略

创建接口接受可选 `imagePolicy`，导入弹窗提供三种选项，任务详情展示实际选择：

| 值 | 选项 | 处理结果 |
| --- | --- | --- |
| `keep_and_recognize`（默认） | 保留图片并识别 | 图片作为长期资源保留；扫描、截图 OCR，照片与图表补充描述。 |
| `text_only` | 仅识别文字 | 不做图片分类或描述，图片区域直接由多模态模型提取可见文字；文章不插图或原页预览。 |
| `images_only` | 仅保留图片 | 图片上传后直接完成，图片状态为 `skipped`；扫描页也保留图片，不调用多模态模型。 |

- 此选项只控制 PDF 图片，原生正文始终保留；Office 等格式仍按 anydoc 规则转换。
- 策略在首次提交时冻结，参与幂等校验，页重试和任务重放沿用原策略；同一幂等键更换策略返回 409。缺省按保留并识别处理。
- 仅文字模式的区域图位于 `uploads/{userId}/document-import/...`，用于失败重试，不是文章资源。页结果持久化完成后尝试清理；清理失败记录日志，可由对象存储临时文件生命周期补偿。失败页保留临时图以便重试，原 PDF 不受影响。
- 仅文字模式识别失败时，即使有原生正文也保留页级失败/重试状态，避免只剩标题却提示导入完成。模型明确确认没有可读文字时，允许空结果。

### PDF 图片保留

- 原 PDF 始终保留在原件对象键。图片区域按原页视觉效果渲染成 PNG，保存到现有对象存储，文章使用 `s4key:`；这保留透明度、蒙版、矢量和叠加文字，并非逐字节复制嵌入图像文件。
- 普通链接、宽幅正文底板和行内等宽代码底色不算正文图片；带可见外观的批注仍保留。相邻/重叠的图片碎片与矢量路径合并为区域。只有唯一匹配普通正文行的锚点才插回段落附近；表格、代码块、多义锚点的图片按页保留，但不再向正文额外追加整页截图。用于校对的原页预览仅在任务详情按需展开；旋转、裁切、复杂 Form 或无法可靠裁切时，整页图作为唯一视觉资源保留。
- 新资源及预览位于 `uploads/{userId}/document-assets/...`，属于长期文章资源，不能应用 OCR 临时文件过期规则。准备未发布时仍受原有 token 清理和引用保护机制约束；删除任务记录不删除已发布图片。
- 页状态中的 `assets` 分别记录对象键、区域坐标、位置、内容类型、识别方式及状态。扫描页 OCR 失败沿用页级重试；已有正文的图片补充识别失败记录为 `failed`，仍用原图和正文成文，详情中明确提示。
- 每张图片识别成功后立即保存，Worker 中断或页重试复用已完成结果。`directPages` 等统计正文来源，图片识别方式在图片明细单独展示。
- 当前区域分组是保守几何规则，不具备 Docling/MinerU 的学习式版面分类精度；原页预览用于保留复杂或不确定布局。Office 等格式仍沿用 anydoc 的输出规则。

### 中断、幂等与恢复

- 浏览器不直接连接 S3；上传地址接口保留 `presignedUrl` 字段名，实际只返回 `/api/upload/object/...`，S3 签名由 Go 内部使用。Go 保存完成后才返回成功，上传失败在弹窗重试。
- 上传尚未完成时后台没有完整原件，也没有导入任务；不能从死信队列重放缺失的文件。
- `/dashboard/imports` 展示当前用户已提交的所有任务；管理员死信页仅展示所有用户中自动重试耗尽的同一批任务。两处重试都保留成功页、原生正文和图片。
- 上传/创建请求仍在进行时请勿关闭页面；收到「已提交后台」后不再需要浏览器参与。
- 每个导入项使用稳定的 `idempotencyKey`；创建请求响应丢失时，以相同键和原始参数重试，
  不重复创建任务。相同键携带不同参数会被拒绝。
- 已确认上传成功的原文件可复用对象键，不因为创建重试而重新上传。
- 同标签页暂存尚未提交的文件，最多 50 个、合计 500 MB；刷新/关闭页面不会保留这些文件。
  认证成功或退出登录会清空暂存并阻止旧异步响应回写，不取消已提交的后台任务。
- 服务端准备使用领取租约和结果校验；过期 Worker 或取消后的迟到结果不能覆盖当前任务。
- 准备失败、取消或结果过期时，最多用 15 秒回收本次准备产生且尚未发布的 OCR 图片；
  提交响应丢失时先核对 Redis 引用，绝不删除已发布页图。引用确认或网络删除失败会保守保留，
  日志记录任务及对象键供运维补偿；中间文件保留策略必须排除长期 `document-assets` 资源。
- 解析阶段失败即使尚无页明细，也可重试原任务，不要求重新上传。
- 手动请求生成文章同样只更新任务并入队，不在 HTTP 请求中执行文章事务；前端继续显示成文阶段。
- 成文与取消/删除共用任务锁；已预留文章 ID 但落库状态未确认时，需先重试成文恢复状态，
  暂不允许取消或删除，避免文章实际生成后又将任务标为取消。

## OCR 处理

anydoc 先直接提取正文；提示需要 OCR 的页渲染为图片，交给本次选择的多模态模型。
未指定模型时使用用户的 `VISION` 用途绑定。图片分类、OCR 与描述均使用这一模型入口。
纯文字页不调用模型；`images_only` 策略跳过所有图片识别，包括扫描页。

每次页级 OCR 尝试只调用一次多模态模型，单次超时为 90 秒。模型缺配置、认证失败或额度不足
明确失败；限流、网络错误、超时和空响应进入原有页级重试。用户或 Worker 取消后停止处理。
没有备用供应商、OCR 优先级或服务降级。识别结果中的上游敏感信息不会写入任务错误。

图片会发送到所选模型的服务地址，按该模型的计费方式消耗额度。

## 统计与重试口径

列表和详情分别展示直接解析和多模态模型的成功页数或文档单元数：

```text
directPages + multimodalPages = donePages
```

- `actualMethods` 是实际成功的方式集合；待识别页不会提前归到某个 OCR 供应商。
- 重试不重复统计或覆盖已成功页；已完成准备的任务不会重新解析、替换已有 OCR 结果。
- 失败任务使用业务重试或管理员重放入口；Asynqmon 的 Run/Retry 只重新投递技术任务，
  不会隐式重置失败领域状态。

## 配置和部署

公开配置见 `apps/api/config.example.toml`；实际配置仍使用忽略提交的 `apps/api/config.toml`：

```toml
[document_import.parser]
command = "petrichor-doc-convert"
timeout_seconds = 300

```

OCR 使用现有模型配置和 `VISION` 用途绑定，无需单独的 OCR 服务配置。
修改配置后重新启动 API 和 Worker。不要将真实密钥提交到仓库。

`apps/api/Dockerfile` 构建固定版本 Rust 转换器，并在现有 API/Worker 共用镜像中安装
Poppler、`prlimit` 及字体；根 `compose.yaml` 的服务拓扑不变，不需要新增转换服务或端口。
Worker 在连接数据库、消费任务前检查转换器与 PDF 工具，缺少依赖时明确启动失败。
本地直接运行 Worker 也必须准备这些工具；推荐通过同一 Docker 镜像验证运行环境。
Rust crate 与锁文件位于 `apps/api/tools/document-converter/`，其许可证及依赖声明随镜像放在
`/usr/share/licenses/petrichor-doc-convert/`。Poppler 使用 Alpine 3.22 的 `25.04.0-r0` 包，
对应源码为 [Poppler 25.04.0](https://poppler.freedesktop.org/poppler-25.04.0.tar.xz)，
打包修改参见 [Alpine aports](https://gitlab.alpinelinux.org/alpine/aports/-/tree/3.22-stable/main/poppler)。
镜像分发者仍需履行第三方许可证和对应源码的分发义务，不能把这些链接当成免除义务的声明。

已安装运行依赖时可显式执行以下离线集成测试（不访问数据库、S3 或 OCR）：

```sh
cd apps/api
PETRICHOR_DOCUMENT_PARSE_RUNTIME_TEST=1 go test ./internal/documentparse -run '^TestRuntimeOfflineDocuments$' -count=1
```

默认测试跳过这组外部工具检查；构建 Linux 测试二进制后也可在 Worker 镜像内以非 root 用户执行，
无需启动真正的 API/Worker 入口或挂载真实配置。

任务仍存于 Redis/Asynq，文章仍使用现有表，**无需数据库迁移**。
Redis 保留、备份和死信管理参见 [运行与运维](./operations.md#视觉导入业务状态)。

## 资源与安全边界

- 原文件最多 100 MB；新 PDF 最多 500 页。
- 单页或非 PDF 文档单元 Markdown 最多 2 MiB UTF-8；整份文件合计最多 16 MiB。
- XLS/XLSB 最多 100 张工作表、每表 10000 行/256 列、展开后合计 100000 个单元格；
  ZIP 实际解压内容最多 64 MiB，不只信任文件声明的大小。
- 待 OCR 图片最多 20 MiB、24 MP；逐页渲染、上传和清理，不把所有页图片保存在内存中。
- 下载、转换、上传均支持取消和超时；子进程无 shell 拼接，Linux 使用 `prlimit` 限制资源，
  其中单文件写入上限为 128 MiB。仅访问配置内的对象存储，不接受用户提供任意下载 URL。
- 解析任务目录（含原文件和当前页）合计最多 256 MiB 可见文件逻辑大小、64 个目录条目；
  仅允许任务根目录和当前页 `unit` 子目录，拒绝符号链接、特殊文件和其他子目录。
  子进程运行前后校验，运行中每 20 ms 有界扫描，超限杀进程组并清理；扫描不加载整个目录，支持取消。
  这是应用层监控，**不是 OS 硬磁盘 quota**，采样间隙可能短暂超额，也不核算已删除但仍打开的文件。
- 加密、损坏、超限或不能完整解析的文件明确失败，不截断成「成功」的残缺文章。
- anydoc、Calamine 采用 MIT；Poppler 为 GPL-2.0-or-later。分发镜像时应保留第三方许可证并履行对应源码提供义务。
